# Tandem operations

This guide describes the implemented single-instance service. Google Cloud staging is deployed; HTTPS, private invitations, typed replies, forced coturn delivery and service restart have passed. The owner also confirmed phone/laptop connectivity across Wi-Fi and cellular. Public production release still requires the acceptance checks below. See [staging deployment](../tandem-app/deploy/staging/README.md) for resources and maintenance commands.

## Configuration and startup

Use Node 24 and the non-root container. Production requires a persistent random ROOM_SIGNING_SECRET and exact HTTPS ALLOWED_ORIGIN values. Configure coturn with TURN_SHARED_SECRET and TURN_URLS; static TURN credentials are rejected in production. Generate room, TURN, and metrics secrets independently and inject them through your hosting secret manager. Never commit them or include them in support tickets.

The app port should be reachable only through the trusted reverse proxy. Set TRUST_PROXY_HOPS to the actual proxy topology. HTTP and socket handshake quotas both use that trust configuration. MAX_HANDSHAKES_PER_MINUTE defaults to 60 per resolved client IP; forwarding headers cannot change the quota key with zero trusted hops. Numeric hop trust requires a fixed route to the app and a proxy that sanitizes forwarding headers. Staging publishes only Caddy, with one hop and Caddy's default forwarding-header handling. See [Express proxy trust](https://expressjs.com/en/guide/behind-proxies/) and [Caddy headers](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy#headers). Edge traffic limits and load validation remain release gates. The in-memory room adapter supports one application instance; do not scale replicas without atomic shared admission and signaling design.

Private Socket.IO connections supply the invitation in `auth.token`, not the URL. The server verifies it before reserving namespace capacity and restricts subsequent room joins to its signed room. Join payloads still require valid, unexpired credentials. Invalid handshake credentials produce a fixed terminal error and the rejected transport closes within one second; raw transports without a namespace still have the configured idle deadline. Existing admitted calls are not forcibly ended merely when an invitation expires, but expired credentials cannot reconnect or renew TURN. A terminal reconnect rejection clears the old peer connection and preserves the page draft.

MAX_CONNECTIONS bounds admitted Socket.IO clients (default 100; staging 20), including middleware reservations during concurrent connection attempts. Each room still admits at most two people. Initial transport handshakes are also rejected when existing transport count reaches capacity; simultaneous handshakes can temporarily exceed that preliminary check, but namespace reservations remain bounded. UNJOINED_TIMEOUT_SECONDS (default/staging 30; range 5–300) closes connections without a call room, including abandoned raw polling transports. Active callers waiting alone in their room remain connected. After leaving a room, an otherwise idle connection closes within one check interval. These bounds protect application resources; they do not replace per-client edge limits or denial-of-service protection.

## Health and metrics

- `/health`: process liveness, HTTP 200. It does not check paid providers.
- `/ready`: HTTP 200 with `{"ready":true}` while running. Shutdown marks readiness false before closing Socket.IO and the HTTP server. A shutdown may finish before a probe sees HTTP 503.
- Deployed shutdown is idempotent: room/provider cleanup runs first, then a five-second deadline destroys remaining raw HTTP/upgrade transports. The process retains its ten-second exit deadline. This bounds unfinished requests during maintenance; it does not provide zero-downtime calls. Node's normal HTTP close leaves active requests and `closeAllConnections` excludes upgraded sockets, so the deadline tracks raw connections. See [Node 24 HTTP closure behavior](https://nodejs.org/docs/latest-v24.x/api/http.html#servercloseallconnections). This change was deployed on 2026-10-08.
- `/metrics`: disabled (404) unless METRICS_TOKEN is configured. Scrapes must supply the exact bearer token in the Authorization header. Restrict scraping to your monitoring network as well as authenticating it.

Metrics expose process uptime/memory, active sockets/rooms/caption streams/provider jobs, request latency buckets, and fixed event counters. No conversation content, identifiers, IPs, or invitation credentials are metric labels. Counters reset on process restart. `client_*` reports are rate-limited diagnostics, not trusted accounting.

Deployed video presentation recovery reports `client_video_playback_retry` when the browser reattaches its received tracks after decoded frames advance without presentation, or an unexpectedly paused element still receives video bytes. It preserves the peer connection, local capture and speaker/volume settings. Attempts stop after two without resumed playback; hidden pages and stalled incoming media do not trigger repair. This counter measures attempts, not successful recovery or network health. The helper needs requestVideoFrameCallback and was deployed on 2026-10-08. Twelve hosted Linux WebKit renewal journeys passed, including one automatic repair followed by moving presentation and twelve forced-pause recoveries; physical Safari coverage remains a release gate.

Configure your platform to redact Authorization headers and request bodies. The browser signing client uses authenticated POST bodies. Its upstream signing provider still uses query text when enabled, so exclude those queries from access logs; signing remains disabled in staging. Browser history contains private invitation links. Do not export browser traces from real conversations without an explicit privacy policy and consent.

Staging release `release-20261008-verified-fonts` serves its existing fonts locally, with upstream licenses and checksums in `tandem-app/public/fonts`. Live browser verification of the landing and both call pages found zero external requests and loaded the expected faces. Call pages no longer request Google Fonts stylesheets or font files; optional recognition/signing services still have their separate provider dependencies when enabled.

The lightweight `Staging health` workflow checks HTTPS liveness/readiness, anonymous metrics/ICE rejection, and trusted app/relay certificates with at least seven days remaining. It creates no rooms, opens no relay allocation, and uses no paid providers or credentials. Failures produce fixed check names/reasons and a failed workflow; certificate days are public metadata. Network operations have ten-second deadlines and inspected HTTP bodies are limited to 1 KiB. It does not verify media delivery, provider accuracy, authenticated metrics, or notification delivery.

Its first push-triggered verification passed in workflow 37796055580. On 2026-10-08 the repository default changed to the fully verified `production-rebuild` branch; old `main` remains unchanged. The workflow is active and its hourly minute-17 schedule is now on the default branch. Manual default-branch run 37857699347 passed all six health/access/certificate checks. Actual scheduled execution has not yet been observed. GitHub schedules may be delayed or dropped under load, so this is a staging canary rather than an availability SLA. Check workflow runs and separately verify your chosen notification channel before production. See [GitHub schedule behavior](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule). No external notification recipient was configured.

Optional recognition uses an independent private inference container (see `tandem-app/deploy/asl/README.md`). `MAX_PREDICTION_REQUESTS` bounds in-flight predictions across all callers, default 2 and range 1–20. Excess requests return a fixed busy response and `Retry-After: 1`; they do not queue. Success/failure releases capacity. Existing per-IP 20 requests/second and complete-response three-second deadlines remain. This protects the model-service boundary; it does not prove model quality, target capacity or network denial-of-service resistance. Recognition remains disabled in staging.

## Failure response

| Signal | Check and response |
| --- | --- |
| Readiness/liveness unavailable | Check process/container events, resource pressure and startup configuration; restore the process before investigating provider quality. |
| `speech_unavailable` rises | Check Google identity, API permissions, quota and caption stream capacity. Typed replies remain the fallback. |
| `speech_limited` rises | Recognition auto-paused on a configured session or incoming-audio idle limit. Video/text continue; a deliberate Start captions action creates a fresh capture binding. |
| `speech_retry` rises | Check network/provider interruptions. Logs contain numeric status codes, not SDK messages. Automatic retries are bounded. |
| `audio_dropped` rises | Check congestion, provider backpressure and abusive submission. Do not increase buffers to hide delayed captions. |
| `client_ice_failed` rises | Check ICE endpoint errors, invitation expiry, TURN reachability and secret alignment. Validate from a separate network. |
| `speech_job_failed` / `avatar_provider_failed` rises | Check optional provider availability. Explicit text delivery remains independent. |
| Memory or active work rises continuously | Verify departure cleanup and load limits. Capture aggregate diagnostics without recording audio or messages. |
| `connection_rejected` rises | Check configured capacity, origin/handshake quotas and traffic pressure; do not increase limits without load evidence. |
| `connection_idle_closed` rises | Connections never joined a call or remained without a room. Active room members are preserved. |

Relay credentials renew before expiry and trigger collision-safe ICE negotiation without replacing local tracks. An expired invitation cannot renew or reconnect. Caption rotation replays only a bounded window of unfinalized audio; long utterances and outages can still lose words. Validate both behaviors using actual providers before claiming seamless long-call support. Staging now offers trusted TURN TLS on port 443 in addition to UDP/TCP 3478. Private/link-local/metadata/loopback peers are denied, TCP relay allocation and CLI disabled, and allocations/bandwidth bounded. Public TLS-only relay delivery and private-permission rejection passed, as did an existing allocation across the installed certificate reload hook. Actual restricted-network and credential-expiry checks remain separate gates.

Optional CAPTION_MAX_SESSION_SECONDS (0–14400) and CAPTION_IDLE_SECONDS (0–300) default to disabled. Staging configures 900 and 15 respectively. Rotation/provider retries preserve the original time limit; leaving, reconnecting or deliberately restarting captions creates a new binding. Idle means missing incoming PCM, not a silent microphone that still sends audio. Limit expiry closes the provider stream, cancels its timers, clears private replay audio and publishes a paused state; incoming audio cannot reopen it automatically. These limits and concurrency controls do not constitute a daily/monthly spending cap. Invalid configured capacities/durations fail startup rather than falling back to a larger allowance.

## Caption choice

The browser release deployed on 2026-10-08 requires Start captions before microphone PCM is submitted for Google transcription. Both roles disclose the provider before that action. Camera/microphone permission still permits WebRTC call media independently; pausing captions does not mute call audio. The choice stays in the current page through connection/media recovery and cached history restoration; a new page starts with captions paused. This is a capture choice, not a completed provider privacy policy. Google project data-logging/retention settings and user evaluation remain production gates.

## Daily caption allowance

CAPTION_DAILY_SECONDS (0 disables; otherwise 15–86400) enables an aggregate application audio allowance per UTC day. CAPTION_BUDGET_FILE must be an absolute path in persistent writable storage. Staging enforces the owner-approved 3600 seconds and mounts a named volume at /app/state, activated on 2026-10-08. Each provider request reserves 15 seconds before opening, then reserves additional blocks before sending PCM. Replay and retries count again; unused credit is never refunded. The result conservatively bounds this application's submitted audio and may pause before actual conversation audio reaches the stated allowance. Google currently rounds requests to one second; the larger reservation blocks are our conservative accounting choice, not a description of provider billing. See [Speech pricing](https://cloud.google.com/speech-to-text/pricing).

Reservations are atomically replaced and flushed before submission, survive app releases/restarts and roll over at UTC midnight. A backward day clock, invalid ledger, storage failure or existing reservation lock refuses new credit. Already reserved credit remains usable until its next reservation. When no credit is available, captions pause and offer Check captions; repeated starts/rejoins cannot reset the ledger. Video and typed replies remain available. A deliberate check after rollover can resume captions.

Protected metrics expose tandem_caption_budget_available (readable/valid ledger), limit_seconds, remaining_seconds and reserved_seconds (only with a valid snapshot), plus fixed speech_daily_budget and speech_budget_unavailable event counters. Counters reset on restart; the ledger does not. The ledger contains only version, UTC day and aggregate reserved milliseconds, with mode 600: no identities, audio or conversation text. This is local single-instance accounting, not a cloud billing cap, an account-wide quota or a multi-replica distributed budget. Other cloud usage and optional providers remain outside it. Initial activation does not import earlier Google usage from before this ledger existed.

Keep the named volume across deployments. Never use compose down --volumes or delete the ledger to restart captions. If a reservation lock survives a crash, stop the app and confirm no other writer uses the volume before removing only the stale lock directory; retain the ledger. Corrupt or lost ledgers require an explicit operational recovery decision. Restoring a stale backup or deleting data can grant additional allowance. An old application image predating this feature does not enforce it even when the volume remains; treat that as a configuration/guard rollback.

## Deployment acceptance

Before public exposure, validate all of the following in staging:

1. Two real devices on different networks connect through TURN; prove relay use with WebRTC statistics, not successful localhost video alone.
2. Run beyond TURN credential expiry and multiple Google recognition rotations; measure media interruption, lost/duplicated captions and latency.
3. Exercise network loss, provider outage, media permission denial, server restart and graceful shutdown. Verify text fallback, drafts and cleanup.
4. Validate invitation expiry, secret rotation, origin rejection and trusted-proxy quotas against the actual hosting topology.
5. Scrape authenticated metrics, test alerts and confirm platform logs redact credentials and conversation content.
6. Complete supported-browser/accessibility checks, Deaf-user evaluation, retention/provider privacy decisions and spending limits.

Staging uses a temporary wildcard-DNS hostname and an attached VM identity. An owned domain, supported-browser/user evaluation and the remaining long-call/privacy/cost gates are required before production release. Infrastructure and caption testing were explicitly approved; further hosting scale or public production release should be reviewed separately.
